# I18n Support Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. (@superpowers:executing-plans)

**Goal:** Add full i18n support so all user-facing strings use `i18n.t()` and `locales/en.json` becomes the source of truth for translations, excluding badge abbreviations.

**Architecture:** Keep translations in `locales/en.json` (simple key → message format). Use `i18n.t()` in UI and background. Shared logic should expose translation keys or accept a translator function to avoid importing `#i18n` in shared modules used by tests.

**Tech Stack:** TypeScript, WXT, React, @wxt-dev/i18n, Node test runner.

**Step 3: Write minimal implementation**

Update `createTimerService` to accept an optional translator:

```ts
export function createTimerService(
  adapter: TimerAdapter,
  options: { t?: (key: string) => string } = {},
) {
  const t = options.t ?? ((key: string) => key)
  // ...
  const buildNotification = (mode: TimerState['mode']) => {
    if (mode === 'work') {
      return {
        title: t('notification_focus_title'),
        message: t('notification_focus_body'),
      }
    }
    return {
      title: t('notification_rest_title'),
      message: t('notification_rest_body'),
    }
  }
}
```
